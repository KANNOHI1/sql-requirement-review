## 罠チェック
- T01 JOIN での行の水増し: 該当なし（JOIN なし。`customers` 1 表のみ）
- T02 INNER JOIN での欠落: 該当なし（JOIN なし）
- T03 NULL 行の脱落（`<>` / `NOT IN` / `=`）: 該当なし。`channel <> 'EC'` は、`channel` が NULL の行を落とす形の条件だが、表定義で NULL 可と明記されているのは `region` と `amount` だけで、`channel`（ドラッグ / GMS / 百貨店 / EC の 4 値）は NULL 可とされていないため、落ちる行はない。「〇〇以外は NULL も含む」という約束は、NULL がありうる場合の話。`is_active` も BOOL で NULL 可の記載がなく、稼働中の絞り込みとして `AND is_active` は TRUE のみを返し、要件どおり

- T05 WHERE と HAVING の位置: 該当なし（集計結果による絞り込みなし。行単位の条件のみ）

- T07 期間境界: 該当なし（期間条件なし）

## 読み下し（Alteryx 対応付き）
1. FROM `dojo.customers`（入力データ）: 得意先マスタを読み込む。表名・列名はすべてテーブル定義と一致（`customer_id`=得意先 ID、`customer_name`=得意先名、`channel`=チャネル、`is_active`=稼働中フラグ）。JOIN なし。
2. WHERE（フィルター・集計前）: `channel <> 'EC'` でチャネルが EC の得意先を除き、`is_active` で稼働中（TRUE）の得意先だけを残す。2 つの条件は AND で両方を満たす行だけが残る。
3. SELECT（フォーミュラ／列選択）: `customer_id`・`customer_name`・`channel` の 3 列をそのまま出力する（計算式なし）。
4. GROUP BY・HAVING・ウィンドウ関数・ORDER BY・LIMIT: いずれもなし。

この SQL が実際に答えている質問: 稼働中で、チャネルが EC ではない得意先の、得意先 ID・得意先名・チャネルの一覧（並び順の指定なし）。
