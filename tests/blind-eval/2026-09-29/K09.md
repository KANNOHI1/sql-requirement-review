## 罠チェック
- T01 JOIN での行の水増し: 該当なし。`sales`→`stores` は stores 自身の `store_id` で結合しており 1 対 1。`targets`→`act` は、`act` が `customer_id` ごとに 1 行にまとめ済みで、`targets` 側も 1 か月（`fiscal_month = '2026-06-01'`）に絞っているので、1 得意先 1 行で水増しされない。
- T02 INNER JOIN での欠落: 該当なし。目標がある得意先が起点で `LEFT JOIN act`。WHERE は左表（`t.fiscal_month`）の列にしか掛けていないので、実績ゼロの得意先も分母に残り、`COALESCE(a.actual, 0)` で 0 円として扱われる。`sales`→`stores` の内部結合は、店舗マスタに全店舗が登録されている前提で、抜けを示す根拠は無い。
- T03 NULL 行の脱落: 該当なし。`<>` / `NOT IN` の除外条件は無い。`amount` の NULL は SUM が無視するが、指標定義で「NULL の行は除外してよい」とされている。
- T04 COUNT と COUNT(DISTINCT) の取り違え: 該当なし。件数を数える処理は無い。
- T05 WHERE と HAVING の位置: 該当なし。集計結果で絞る条件は要件に無く、SQL にも無い。
- T06 タイムゾーン: 該当なし。`sale_ts`（TIMESTAMP）を `DATE(s.sale_ts, 'Asia/Tokyo')` で JST の日付に変換してから比較している。
- T07 期間境界: 該当なし。JST 変換後の DATE 型に対する BETWEEN なので、6/30 の終日が含まれる。月末日の決め打ちも要件（6月＝30日まで）と合っている。
- T08 返品・マイナス行・NULL 金額の扱い: 該当なし。`amount > 0` のような除外は無く、マイナス行を含めて合計するので、「売上（返品を差し引く）」の定義どおり。NULL 金額は SUM が無視し、定義上も許容。
- T09 指標定義のズレ: 該当なし。`sales.amount`（税抜・実売金額）を使っており、定価 × 数量ではない。「目標達成率（全体）」の定義（Σ売上 ÷ Σ目標、税抜、返品を差し引く、月は JST）と一致。
- T10 最新スナップショットの選び方: 該当なし。在庫の表は使っていない。
- T11 ゼロ除算・比率の計算: 該当なし。Σ実績 ÷ Σ目標の合計同士の比率で、行ごとの率の平均ではない。目標が 1 件も無ければ NULL が返るだけで、目標の合計が 0 になるのは全得意先の目標が 0 円の場合のみで、要件上ありえないため問題としない。
- T12 ORDER BY 無しの LIMIT: 該当なし。上位 N 件の要件は無く、LIMIT も無い。
- T13 表・列の選び違い: 該当なし。使っている表（`dojo.sales`、`dojo.stores`、`dojo.targets`）と列（`sales.sale_ts` / `amount` / `store_id`、`stores.store_id` / `customer_id`、`targets.customer_id` / `fiscal_month` / `target_amount`）は、すべてテーブル定義に存在する。取引は正本の `sales` を使っており、生データの `sales_raw` ではない。
- T14 元データの重複行: 該当なし。重複を除く前の `sales_raw` ではなく、取引の正本である `sales` を使っている。
- T15 文字列の一致ミス: 該当なし。文字列の比較は無く、結合は ID 列（`store_id`、`customer_id`）のみ。

## 読み下し（Alteryx 対応付き）
表名・列名の照合（先に実施）:
- `dojo.sales`（取引の正本）→ 要件の「売上」の元。`sale_ts`＝取引日時、`amount`＝実売金額（税抜）、`store_id`＝店舗の紐づけ用。すべて定義にある。
- `dojo.stores` → 店舗から得意先を引くための表。`store_id`、`customer_id` は定義にある。
- `dojo.targets` → 要件の「目標」。`customer_id`、`fiscal_month`（月初日）、`target_amount`（税抜・月次売上目標）は定義にある。
- 定義に無い表・列は無し。

CTE `act`（先に読む）:
- FROM `dojo.sales` JOIN `dojo.stores`（入力データ＋結合ツール。`store_id` で内部結合＝J 出力のみ）: 取引に得意先 ID を付ける。
- WHERE `DATE(s.sale_ts, 'Asia/Tokyo') BETWEEN 2026-06-01 AND 2026-06-30`（フィルター・集計前）: JST の 2026 年 6 月 1 日〜30 日の取引だけ残す。
- GROUP BY `st.customer_id` + `SUM(s.amount)`（集計ツール）: 得意先ごとの 6 月の実績（マイナス行を含めた合計、NULL は無視）。

メインクエリ:
- FROM `dojo.targets t`（入力データ）: 目標表。
- LEFT JOIN `act a` ON `t.customer_id = a.customer_id`（結合ツールの J＋L 出力＝左の目標を全部残す）: 目標のある得意先に 6 月の実績を付ける。実績が無い得意先は実績が NULL になる。
- WHERE `t.fiscal_month = DATE '2026-06-01'`（フィルター・集計前）: 2026 年 6 月分の目標行だけ残す。
- SELECT `SUM(COALESCE(a.actual, 0)) / SUM(t.target_amount)`（集計ツール＋フォーミュラ）: 実績の NULL を 0 として全得意先分を合計し、目標の合計で割る。GROUP BY が無いので全体で 1 行。
- ORDER BY / LIMIT / ウィンドウ関数 / HAVING: なし。

この SQL が実際に答えている質問: 2026 年 6 月（JST）に目標が設定されている得意先について、6 月の税抜実売金額（返品などのマイナス行を含む）の合計を、6 月の目標金額の合計で割った、全体の目標達成率はいくつか。
