# ブラインド評価

Skill の検出精度を測る手順と結果。`tests/check_cases.py` は「ケース自体が嘘でないか」を確かめるだけで、Skill が罠を見つけられるかは別に測る必要がある。

## 手順

1. `python tests/make_blind_inputs.py C13 C14 C15` で、ケースごとに「要件・SQL・テーブル定義・指標定義」だけを書いた入力ファイルを作る（`trap` / `expected` / `reference` は入れない）
2. 答えを知らない別モデル（サブエージェント）に次を指示する
   - 読んでよいのは `skill/SKILL.md`、`skill/references/trap-checklist.md`、入力ファイルの 3 つだけ
   - `tests/` 配下は開かない（正解が入っている）
   - SKILL.md の手順 1〜4・6 を実行し、出力形式どおりに返す。`bq` は無いので手順 5 は「読解のみ（未実行）」
3. 判定と、罠チェックで「該当」にした ID を `cases.yaml` の `expected` / `trap` と突き合わせる
4. 出力全文を `tests/blind-eval/<日付>/<ケース ID>.md` に保存し、下の表に 1 行足す

合格の基準: 罠ありケースは判定「不一致」かつ該当 ID に正解の罠を含む。正しいケース（K）は判定「合致」。K で「要確認」が出たら不合格として扱い、何を根拠に要確認にしたかを気づきに書く（正しい SQL を止めるのも失敗）。
